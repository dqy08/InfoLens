Privacy Policy for Info Highlight

Last updated: September 2026

Data We Process

When you invoke the extension (toolbar icon or page context menu) on the webpage or PDF you are viewing, it reads the visible article/body text of that page. What happens next depends on how analysis is run:

  • Cloud (default until an on-device model is ready): the extracted text is sent to our backend server at api.info-lens.app.
  • On-device (after you agree on the setup page): the text stays on your computer. The extension downloads about 800 MB of model weights from Hugging Face or ModelScope (you choose which) and keeps them locally.

This happens only when you invoke the extension on the page you are viewing at that moment. The extension does not access any other tabs or pages.

Separately, and without page content: we use an anonymous client id (a random UUID). It is stored as a first-party cookie on info-lens.app (shared with our website and our other Info Lens extensions) and cached in the extension’s local storage. Installing, updating, uninstall events, optional survey answers, and analysis-run usage pings may include this id together with the extension id and version so we can estimate usage frequency and reconnect the same browser after reinstall. If you submit the uninstall survey, we receive the reasons and comment you typed. The id is not linked to your name, email, or Google account.

Also without page content: after each analysis run (up to 32 text segments, including when you cancel mid-run or the run fails), the extension sends a small usage ping—extension id, version, anonymous client id, whether analysis used on-device or cloud, outcome, how many segments were attempted / succeeded, and how many were served from the local analysis cache (no new inference). This ping never includes page text or the page URL.

Also without page content: when an on-device model setup finishes (success, failure, or cancel), the extension may send a one-shot setup log—extension id, version, outcome, duration, download source (Hugging Face or ModelScope), and a short error string if it failed. No page text.

How We Use It

The page text is used solely to compute information-density scores and return a heatmap overlay on that page. On-device analysis does the same computation locally and does not send the page text to our server. Version events, optional survey answers, anonymous analysis-run counts (including the anonymous client id used only to operate and improve the product), and on-device setup logs are used only for that purpose. No other use is made of this data.

Data We Do Not Collect

We do not collect or store: names, email addresses, passwords, financial information, health information, personal communications, or any other personally identifiable information. We do not track your browsing history across pages or sessions.

Data Storage & Retention

  • Page text sent to our server is processed transiently to generate the heatmap and is not stored on our server after the response is returned.
  • Our server keeps a temporary, in-memory counter to distinguish visitor sessions for basic operational purposes (e.g., diagnosing issues). This counter is not written to disk, is not linked to any other data, and is cleared whenever the server restarts.
  • Optional uninstall-survey answers are stored so we can improve the product. Install/update/uninstall events and analysis-run usage pings may store the extension id, version, anonymous client id, and the counters described above (no page content). On-device setup logs store the fields described above (no page content).
  • Heatmap results, display preferences, and on-device model status are saved locally in your browser (via the extension's local storage). Model weights, if you download them, stay in the browser cache on your device. You can clear both from the extension's options page. Clearing site data for info-lens.app resets the anonymous client id cookie.

Third-Party Sharing

We do not share, sell, or transfer page content to third parties. We do not use your data for advertising. If you agree to on-device analysis, the extension contacts Hugging Face or ModelScope only to download model weights; those services do not receive the page text.

Security

All data sent to our server is transmitted over HTTPS.

Permissions

The extension requests the minimum permissions needed for its single purpose (highlighting informative words on the active page):

  • activeTab / scripting: to read and highlight text on the page you are currently viewing, only when you invoke the extension
  • storage: to save heatmap results and your preferences locally in your browser
  • offscreen: to run the on-device model when you have enabled it
  • contextMenus: so you can invoke the same highlight from the page's right-click menu

Optional host access is requested only when needed: file:// for local PDF files, and Hugging Face or ModelScope origins to download model weights after you agree. Cloud analysis does not use host permissions; page text is sent to our backend by the extension’s background service worker via a standard cross-origin HTTPS request. The page you are viewing never talks to our server directly.

Changes to This Policy

If our data practices change, we will update this policy and the Chrome Web Store listing accordingly.
